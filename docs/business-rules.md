# SmartWMS Business Rules

This document defines the deterministic Day 1 business decision layer. These rules are implemented
in `backend/app/services/business_decisions.py` and are designed to be consumed by a future agentic
AI layer.

The LLM should explain these results. It should not invent calculations, reason codes, risk labels,
or purchase decisions.

## Terminology

These concepts are intentionally separate:

- `available_quantity`: stock currently available after reservations.
- `open_demand_quantity`: unfulfilled open order demand for the same SKU and warehouse.
- `low_stock_candidate`: available stock is below the SKU reorder point.
- `demand_shortfall_quantity`: open demand that cannot be covered by available stock.
- `stockout_risk`: deterministic risk label based on available stock and open demand.
- `inventory_position`: on-hand plus inbound minus reserved.
- `replenishment_candidate`: operational flag for review, not an automatic purchase decision.
- `reorder_quantity`: calculated only when target stock and inbound data are available.
- `replenishment_priority_score`: prototype heuristic score for sorting review candidates.

## Formulas

Available quantity:

```text
available_quantity = on_hand_quantity - reserved_quantity
```

Validation:

- `on_hand_quantity` and `reserved_quantity` cannot be negative.
- `reserved_quantity` cannot exceed `on_hand_quantity` in the MVP.
- Negative availability is rejected instead of silently accepted.

Open demand:

```text
open_demand_quantity =
    sum(open/unfulfilled order line quantities for the same SKU and warehouse)
```

Low-stock candidate:

```text
low_stock_candidate = available_quantity < reorder_point
```

Demand shortfall:

```text
demand_shortfall_quantity = max(open_demand_quantity - available_quantity, 0)
```

Inbound quantity:

```text
inbound_quantity = 0
```

The MVP uses an explicit inbound provider abstraction and a safe demo default of `0`. Future
versions can connect purchase orders, ASNs, or transfer inbound data behind the same interface.

Inventory position:

```text
inventory_position = on_hand_quantity + inbound_quantity - reserved_quantity
```

Inventory position is not the same as available quantity because it includes inbound supply.

## Stockout Risk

Current version:

```text
if available_quantity <= 0:
    stockout_risk = HIGH
elif available_quantity < open_demand_quantity:
    stockout_risk = HIGH
else:
    stockout_risk = LOW
```

This is a deterministic business-rule classifier, not a predictive ML model.

## Replenishment Candidate

Baseline rule:

```text
replenishment_candidate =
    low_stock_candidate == true
    OR demand_shortfall_quantity > 0
```

Reason codes are generated by the backend:

- `AVAILABLE_BELOW_REORDER_POINT`
- `OPEN_DEMAND_EXCEEDS_AVAILABLE`
- `HIGH_STOCKOUT_RISK`

## Reorder Quantity

Baseline interface:

```text
reorder_quantity = target_stock - inventory_position
```

The returned value is clamped at `0`. If `target_stock` or inbound data is unavailable, the service
returns:

```json
{
  "reorder_quantity": null,
  "insufficient_data": true,
  "reason": "INSUFFICIENT_DATA"
}
```

The current demo dataset has `target_stock` and uses inbound quantity `0`, so demo reorder quantity
can be calculated. This value is a planning signal, not a purchase order.

## Replenishment Priority Score

This score is a prototype business heuristic for sorting replenishment candidates. It is not
mathematically optimal.

Component scores:

```text
stock_gap_score = clamp((reorder_point - available_quantity) / reorder_point, 0, 1)
demand_pressure_score = clamp(open_demand_quantity / available_quantity, 0, 1)
lead_time_score = clamp(supplier_lead_time_days / 14, 0, 1)
```

If `available_quantity <= 0` and demand exists, `demand_pressure_score` is `1`.

Weighted score:

```text
replenishment_priority_score =
    0.40 * stock_gap_score
  + 0.45 * demand_pressure_score
  + 0.15 * lead_time_score
```

If `stockout_risk = HIGH`, the score has a floor of `0.75`.

Priority bands:

```text
0.00        -> none
0.01 - 0.34 -> low
0.35 - 0.69 -> medium
0.70 - 1.00 -> high
```

Supplier reliability is returned as context only. The MVP does not label suppliers as risky.

## What This System Does Not Claim

- It is not a complete WMS.
- It does not make autonomous purchase decisions.
- It does not execute inventory changes, orders, transfers, or procurements.
- Replenishment priority is a prototype heuristic.
- Stockout risk is deterministic, not predictive ML.
- Synthetic data is used for demonstration.
- Reorder quantity is not calculated without sufficient data.

Future WMS-domain extensions may include purchase orders, inbound ASNs, transfer orders, lot and
serial tracking, handling units, warehouse execution workflows, transportation management, and
human approval flows.
